# desktop

The Bakery's Desktop app: Wails 3 (Go) with a Svelte 5 runes + TypeScript +
Vite + Tailwind CSS v4 frontend on `@bakery/ui`, built with Bun. It runs on a
person's own machine, connects to one or more Bakeries through their API
(outbound HTTPS and SSE only) and will run that person's Agents with the local
`claude` CLI.

It hosts no bounded context of its own: it is a client of `services/api`, like
`apps/web`, and keeps only a cache and, later, the Agents' local checkouts.

```sh
task desktop:dev     # the window with live reload (needs a display; Vite on 127.0.0.1:4990)
task desktop:build   # the binary, bin/bakery-desktop (wails3 build)
task desktop:serve   # no window: the frontend and the Go methods on http://127.0.0.1:4991
task desktop:e2e     # the frontend in headless Chromium against serve (needs task desktop:serve)
task desktop:check   # gofmt, go vet, go test, svelte-check, tsc
```

`task dev` does not start it: the window needs a display. Needs `wails3`
(v3.0.0-beta.18, `go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.18`)
on `PATH` and Wails' Linux libraries (`wails3 doctor`).

## Modes

- **No arguments**: the window. The frontend calls the `Desktop` service
  (`desktop.go`) through the bindings `wails3 generate bindings` writes to
  `frontend/bindings` (committed, regenerated by every build).
- **`serve [--addr 127.0.0.1:4991]`**: no window. Serves the embedded frontend
  and the same `Desktop` methods as `POST /rpc/<Method>` (a JSON array of
  arguments in, `{"result": …}` or `{"error": "…"}` out; an unlisted method is
  404) and live updates as SSE on `GET /rpc/events`. Loopback addresses only,
  and a taken port fails instead of moving. This is how a headless browser
  drives the real Go code.
- **`version`**: prints the version.

`frontend/src/lib/desktop.ts` is the frontend's only way to the Go side: one
typed function per `Desktop` method, choosing the bindings in the window and
`/rpc` in a browser. A new method goes in `desktop.go`, in the list in
`rpc.go`, and in `desktop.ts`.

The unit root (`package.json` here, not in `frontend/`) is the member of the
root Bun workspace, so `frontend/` and `e2e/` resolve the same dependencies;
`vite` runs with `frontend` as its root. `build/` holds Wails' build
Taskfiles and Linux packaging (AppImage, deb, rpm, Arch), trimmed to Bun and
Linux; `wails3 update build-assets` brings back macOS and Windows when they
are packaged.
